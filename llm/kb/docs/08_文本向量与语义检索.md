# 文本向量与语义检索

## 什么是文本向量

文本向量（embedding，也叫嵌入）是用一串数字表示一段文字的含义。意思相近的文字，向量也相近。例如"如何降低显存占用"和"怎样节省显存"的向量会很接近，尽管它们用词不同。

向量之间的相似度通常用余弦相似度衡量，取值范围是 -1 到 1，越接近 1 越相似。如果先把向量归一化（长度变为 1），余弦相似度就等于两个向量的点积，计算更快。

## 向量模型

向量模型一般基于 BERT 这类编码器结构，用大量"问题—相关段落"数据通过对比学习训练：让相关的问题和段落向量靠近，不相关的远离。

中文常用的开源向量模型是北京智源人工智能研究院（BAAI）发布的 BGE 系列：
- bge-small-zh-v1.5：约 2400 万参数，向量维度 512，模型文件约 95MB，CPU 上也能快速运行，适合普通电脑；
- bge-base-zh-v1.5：约 1 亿参数，向量维度 768，效果更好，速度较慢；
- bge-m3：支持多语言和长文本，模型较大。

使用 BGE 中文模型检索时，建议在问题前面加上指令"为这个句子生成表示以用于检索相关文章："，文档则不需要加。BGE 模型取第一个位置（CLS）的输出作为整段文字的向量。

## 向量索引

知识库较小时（几万段以内），可以直接把所有向量存成一个矩阵，查询时和问题向量做一次矩阵乘法，取相似度最高的若干条，这叫暴力检索，结果精确，速度也足够快。

知识库很大时（百万段以上），需要近似最近邻（ANN）索引来加速，例如 HNSW（分层可导航小世界图）、IVF（倒排文件）等。常用的工具有 FAISS、hnswlib、Milvus 等。近似索引会牺牲少量准确率来换取速度。

## 向量检索的局限

向量检索擅长理解语义，但对精确的数字、型号、专有名词、生僻词不够敏感，有时会把"字面不同但主题相似"的段落排在前面。所以实际系统中通常把向量检索和 BM25 关键词检索结合使用，取长补短。

## 更新知识库

更换向量模型后，必须用新模型重新计算所有文档的向量，因为不同模型的向量空间互不兼容。只增加或修改少量文档时，可以只计算变化部分的向量，其余沿用缓存，节省时间。
