# 模型量化与推理加速

## 什么是量化

量化是用更少的比特数存储模型参数。模型训练时通常使用 16 位或 32 位浮点数，量化后可以用 8 位、4 位甚至更少的比特表示每个参数。量化能大幅减少模型的内存占用，并加快推理速度，代价是精度有少量损失。

一般来说，8bit 量化几乎不损失效果；4bit 量化的效果损失也很小，是在普通电脑上运行模型的首选；低于 3bit 时效果会明显下降。模型越大，对量化越不敏感。

## 分组量化

为了减少精度损失，量化通常按小组进行：把参数分成每组 32 个或更多，每组单独计算一个缩放系数，再把组内每个参数映射成低比特整数。这样即使不同位置的参数数值范围差异很大，也能较好地保留信息。

## GGUF 格式与 llama.cpp

llama.cpp 是一个用 C/C++ 编写的大语言模型推理引擎，由 Georgi Gerganov 开发，专门针对 CPU 做了大量优化，也支持显卡加速。它使用 GGUF 格式的模型文件，一个文件里包含模型权重、分词器和对话模板。

GGUF 提供多种量化类型，常见的有：
- Q8_0：8bit 量化，效果最接近原模型，体积约为 16 位模型的一半；
- Q5_K_M：约 5.7bit，效果和体积比较平衡；
- Q4_K_M：约 4.8bit，体积约为 16 位模型的 30%，是最常用的推荐选择；
- Q2_K、Q3_K 系列：体积更小，但效果下降明显。

例如 Qwen2.5-1.5B-Instruct 的 Q4_K_M 版本大约 1GB，普通电脑就能流畅运行。在 Python 中可以通过 llama-cpp-python 库调用 llama.cpp。

## 其他量化方法

- GPTQ 和 AWQ：主要用于显卡推理的 4bit 量化方法，需要少量校准数据；
- bitsandbytes：常与 QLoRA 配合，用于训练时量化底座模型；
- 动态量化：PyTorch 可以在 CPU 上把线性层动态量化为 int8。

## 推理速度的瓶颈

生成文字时，模型每输出一个词元，都要把全部参数从内存读一遍。因此对于小批量推理，速度主要受内存带宽限制，而不是计算能力。一个粗略的估算方法是：

每秒生成词元数 ≈ 内存带宽 ÷ 模型文件大小

例如内存带宽约 40GB/s 的电脑运行 1GB 的量化模型，理论上限约为每秒 40 个词元，实际通常能达到上限的一半左右。这也是为什么量化能提速：模型变小了，每个词元需要读取的数据就少了。

## 其他加速手段

- KV 缓存：保存已经计算过的键和值，避免重复计算；
- 控制上下文长度：输入越长，处理输入（预填充）的时间越长；
- 使用多线程：线程数一般设为 CPU 的物理核心数；
- 投机解码：用一个小模型先猜多个词元，再由大模型一次性验证，可以加速大模型推理。
