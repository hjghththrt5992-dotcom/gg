# LoRA 与参数高效微调

## 全参数微调的问题

全参数微调会更新模型的所有参数。使用 Adam 优化器训练时，每个参数除了权重本身，还需要保存梯度和两个优化器状态（一阶动量和二阶动量）。以 FP32 计算，每个参数约需 16 字节。一个 1.5B 的模型全参数微调约需 24GB 以上内存，还不算中间激活值，普通电脑很难承受。

## LoRA 的原理

LoRA（Low-Rank Adaptation，低秩适配）由微软的研究人员在 2021 年提出。它的思路是：冻结原模型的全部权重，只在部分线性层旁边加一个小的"旁路"。

对于一个 d × k 的权重矩阵 W，LoRA 不直接修改 W，而是学习一个增量 ΔW = B × A。其中 B 是 d × r 的矩阵，A 是 r × k 的矩阵，秩 r 远小于 d 和 k（常用 8、16 或 32）。前向计算变为：

输出 = W·x + (α / r) · B·A·x

训练开始时 B 初始化为全零，A 随机初始化，因此一开始 ΔW 为零，模型行为与原模型完全相同。

## 为什么 LoRA 省资源

以一个 1536 × 1536 的矩阵为例，全参数微调要训练约 236 万个参数；而 r = 16 的 LoRA 只需训练 1536 × 16 × 2 ≈ 4.9 万个参数，约为原来的 2%。对整个模型来说，LoRA 通常只训练 0.1%～1% 的参数。

由于要训练的参数极少，梯度和优化器状态占用的内存也极少，主要内存开销变成了原模型权重和中间激活值。这使得在普通电脑的 CPU 上微调 0.5B～1.5B 的模型成为可能。

## 关键超参数

- 秩 r：越大表达能力越强，但参数越多。一般任务用 8～16 就足够。
- 缩放系数 α（lora_alpha）：控制旁路输出的大小，常设为 r 的 2 倍。
- 目标模块：把 LoRA 加在哪些层上。只加在注意力的 q_proj、v_proj 上最省资源；加在全部线性层（q_proj、k_proj、v_proj、o_proj、gate_proj、up_proj、down_proj）上效果通常更好。
- 学习率：LoRA 的学习率通常比全参数微调大，常用 1e-4 到 3e-4。

## 合并与部署

训练完成后，LoRA 权重可以单独保存，通常只有几十 MB。部署时既可以"底座模型 + LoRA"一起加载，也可以把 B·A 直接加到原权重 W 上，合并成一个普通模型，推理时没有任何额外开销。合并后的模型还可以转换成 GGUF 格式并量化，用 llama.cpp 高速运行。

## QLoRA

QLoRA 是 2023 年提出的改进方法：把冻结的底座模型量化成 4bit（NF4 格式）存储，只有 LoRA 部分用 16 位训练。它进一步把显存需求降低到原来的约四分之一，使得在单张 48GB 显卡上就能微调 65B 的模型。QLoRA 依赖 GPU 上的量化计算库，在 CPU 上一般使用普通 LoRA。

## 其他参数高效微调方法

除了 LoRA，常见的参数高效微调（PEFT）方法还有 Prefix Tuning、Prompt Tuning 和 Adapter 等。LoRA 因为效果好、实现简单、推理无额外开销，是目前最流行的选择。Hugging Face 的 peft 库实现了这些方法。
